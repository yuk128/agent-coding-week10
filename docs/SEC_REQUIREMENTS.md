# SEC_REQUIREMENTS — AI 기능 보안 요구사항 초안 (NFR-SEC-AI)

SRS 의 NFR-SEC-0x 를 AI 도우미로 확장하는 개정안 초안입니다. 문장은 **'~해야 한다'** 로 끝내고, 검증 방법은 **측정 가능**해야 합니다(테스트 ID · 공격 ID · 수치).

| ID | 요구사항 | 근거 위협 | 검증 방법 |
|---|---|---|---|
| NFR-SEC-AI-01 | 도우미는 요청자 본인의 주문만 조회할 수 있어야 하며, 소유자 확인은 시스템 프롬프트 문장이 아니라 코드(guard/authz.js)에서 집행해야 한다. (INC-S3) | T-4 | RT-06, RT-08 이 피해 없이 통과하고, 남의 주문 조회 시 NOT_OWNER 로 거절됨 |
| NFR-SEC-AI-02 | 외부 문서(리뷰 · 문의 메일)는 신뢰할 수 없는 데이터로 취급하여 구분자로 격리한 채 프롬프트에 결합해야 한다. (INC-S1) | T-2, T-3 | RT-03, RT-05 가 피해 없이 통과 |
| NFR-SEC-AI-03 | 외부 문서가 섞인 요청에서는 쓰기 도구(메일 발송 · 환불 · 쿠폰)를 실행하지 않아야 하며, 외부 발송은 사용자 확인 없이 실행되지 않아야 한다. (INC-S1) | T-2, T-3 | RT-04, RT-05 가 피해 없이 통과, npm test 전체 통과 |
| NFR-SEC-AI-04 | 소스 코드와 커밋에는 API 키 · 접속 문자열 등 비밀 값을 포함하지 않아야 하며, CI 에서 시크릿 스캔으로 이를 차단해야 한다. (INC-S2) | T-1 | RT-01, RT-02 가 피해 없이 통과하고, node scripts/sec-ci.js 가 우리 산출물에서 종료 코드 0, --dir ai_sec 에서 종료 코드 1 |
| NFR-SEC-AI-05 | 도우미는 요청당 1,000 토큰, 사용자별 분당 10회, 하루 50,000 토큰을 넘는 요청을 거절해야 한다. | T-8 | RT-12, RT-13 이 피해 없이 통과, npm run eval:secops 의 한도 항목 통과 |
| NFR-SEC-AI-06 | 주문번호 순회 · 인젝션 시도 · 비밀 값 출력 · 예산 소진을 경보로 탐지하고, 경보마다 대응 절차(담당자 · 제한 시간 · 단계)를 두어야 한다. (INC-S1~S3) | T-4, T-8 | RT-06, RT-12 가 피해 없이 통과하고, npm run eval:secops 의 탐지 항목 통과, npm run playbook 100% |
