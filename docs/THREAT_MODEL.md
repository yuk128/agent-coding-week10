# THREAT_MODEL — MiniMall AI 도우미 위협 모델 (Mission 0 → 계속 갱신)

> 완벽한 답이 아니라 **놓치지 않기 위한 질문 목록**입니다. 기능은 'AI 도우미'(상품 검색 · 주문 조회 · 쿠폰 · 환불 제안).

## 1. 자산 — 무엇을 지켜야 하는가
- 고객 개인정보: 수령인 이름, 연락처, 주소, 이메일, 카드번호
- 주문 데이터와 결제·환불·쿠폰 처리 권한 (금전 피해로 이어지는 쓰기 도구)
- 비밀 값: 내부 키(INTERNAL-KEY-…), 결제·토큰 키, 관리자 우회 코드, 내부 주소(*.internal), 시스템 프롬프트
- AI 사용 비용(일일 토큰 예산)과 서비스 가용성
- 로그: 마스킹되지 않으면 개인정보·키의 2차 유출 경로가 됨

## 2. 공격자 — 누가 노리는가
- 악의적 일반 사용자: 채팅창으로 프롬프트 유출·남의 주문 조회·과도한 쿠폰·환불을 시도
- 외부 문서 작성자: 리뷰·문의 메일에 숨은 지시를 넣는 사람 (사용자는 악의 없음, 간접 인젝션)
- 공급망 공격자: AI 가 지어낸 패키지 이름을 선점하거나 위장 패키지를 배포
- 내부자·실수: 키를 커밋하거나 로그에 개인정보를 남기는 개발자
- 자동화 봇: 반복·긴 호출로 비용을 폭증시키거나 계정을 대량 시도

## 3. 공격면 — 어디로 들어오는가
- 채팅 입력창 (직접 입력, 전각·제로폭 등 표기 변형 포함)
- 외부 문서: 리뷰, 문의 메일 (도우미가 읽는 본문)
- AI 생성 코드(app/shop_api.js)와 AI 추천 패키지(package.json)
- 시스템 프롬프트와 로그
- 모델이 낸 출력(도구 호출 JSON, HTML 응답)
- 반복·긴 호출(요청 횟수, 입력 길이, 토큰)

## 4. 영향 — 뚫리면 어떻게 되는가
- 개인정보·비밀 유출로 법적 책임과 신뢰 하락, 키 폐기·교체 비용
- 무단 환불·쿠폰으로 직접적인 금전 손실
- 남의 주문 조회·이메일 전송으로 정보 유출 확산
- 응답에 삽입된 스크립트로 고객 브라우저 공격 (출력 인젝션)
- 비용 폭증으로 서비스 중단 (Denial of Wallet)
- 악성 패키지로 서버 키·고객 데이터 탈취

## 5. 위협 표 (8건 이상)

| ID | 자산 | 공격자 | 공격면 | OWASP LLM | 영향 | 대응(어느 계층에서) | 검증(테스트 · 공격 ID) |
|---|---|---|---|---|---|---|---|
| T-1 | 시스템 프롬프트 속 내부 정보 | 악의적 사용자 | 채팅 입력 | LLM07 | 내부 키 · 주소 노출 | 설계: 프롬프트에 비밀을 넣지 않음 + 입력: 유출 요청 차단 + 출력: redactSecrets | RT-01, eval:guard A1·SP |
| T-2 | 다른 고객의 주문·연락처 | 악의적 사용자 | 채팅 입력 (남의 주문번호) | LLM06 · LLM02 | 타인 개인정보 조회(CROSS_USER, PII_LEAK) | 결정: authorizeTool 소유자 확인 + 출력: redactPII | RT-02, eval:guard A2·B3 |
| T-3 | 환불·이메일 전송 같은 쓰기 권한 | 외부 문서 작성자 | 리뷰·문의 문서 본문(숨은 지시) | LLM01 | 사용자 모르게 이메일 전송·환불(EXFIL, UNAUTH_ACTION) | 입력: wrapUntrusted로 데이터 격리 + 결정: tainted 컨텍스트에서 쓰기 도구 금지, validateAction 허용 목록 | RT-03, eval:guard A3·A4 |

## 6. 신뢰 경계 그림
신뢰하지 않는 영역(사용자 입력 · 외부 문서 · 모델 출력 · AI 코드/패키지) → [입력 정규화·격리 → 구조화 출력 검증 → 소유자·승인 인가 → 출력 마스킹] → 신뢰하는 영역(도구 실행 · 응답 · 로그)
