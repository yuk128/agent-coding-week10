# THREAT_MODEL — MiniMall AI 도우미 위협 모델 (Mission 0 → 계속 갱신)

> 완벽한 답이 아니라 **놓치지 않기 위한 질문 목록**입니다. 기능은 'AI 도우미'(상품 검색 · 주문 조회 · 쿠폰 · 환불 제안).

## 1. 자산 — 무엇을 지켜야 하는가
- 고객 개인정보: 수령인 이름, 연락처, 주소, 이메일, 카드번호
- 주문 데이터와 결제·환불·쿠폰 처리 권한 (금전 피해로 이어지는 쓰기 도구)
- 비밀 값: 내부 키(INTERNAL-KEY-…), 결제·토큰 키, 관리자 우회 코드, 내부 주소(*.internal), 시스템 프롬프트
- AI 사용 비용(일일 토큰 예산)과 서비스 가용성
- 로그: 마스킹되지 않으면 개인정보·키의 2차 유출 경로가 됨

## 2. 공격자 — 누가 노리는가
- 악의적 일반 사용자: 채팅창으로 프롬프트 유출·남의 주문 조회·과도한 쿠폰·환불을 시도
- 외부 문서 작성자: 리뷰·문의 메일에 숨은 지시를 넣는 사람 (사용자는 악의 없음, 간접 인젝션)
- 공급망 공격자: AI 가 지어낸 패키지 이름을 선점하거나 위장 패키지를 배포
- 내부자·실수: 키를 커밋하거나 로그에 개인정보를 남기는 개발자
- 자동화 봇: 반복·긴 호출로 비용을 폭증시키거나 계정을 대량 시도

## 3. 공격면 — 어디로 들어오는가
- 채팅 입력창 (직접 입력, 전각·제로폭 등 표기 변형 포함)
- 외부 문서: 리뷰, 문의 메일 (도우미가 읽는 본문)
- AI 생성 코드(app/shop_api.js)와 AI 추천 패키지(package.json)
- 시스템 프롬프트와 로그
- 모델이 낸 출력(도구 호출 JSON, HTML 응답)
- 반복·긴 호출(요청 횟수, 입력 길이, 토큰)

## 4. 영향 — 뚫리면 어떻게 되는가
- 개인정보·비밀 유출로 법적 책임과 신뢰 하락, 키 폐기·교체 비용
- 무단 환불·쿠폰으로 직접적인 금전 손실
- 남의 주문 조회·이메일 전송으로 정보 유출 확산
- 응답에 삽입된 스크립트로 고객 브라우저 공격 (출력 인젝션)
- 비용 폭증으로 서비스 중단 (Denial of Wallet)
- 악성 패키지로 서버 키·고객 데이터 탈취

## 5. 위협 표 (8건 이상)

| ID | 자산 | 공격자 | 공격면 | OWASP LLM | 영향 | 대응(어느 계층에서) | 검증(테스트 · 공격 ID) |
|---|---|---|---|---|---|---|---|
| T-1 | 시스템 프롬프트 및 내부 비밀 정보 | 악의적 사용자 및 외부 문서 작성자 | 채팅 입력 및 외부 문서 | LLM01, LLM07 | 내부 접속 주소, 관리자 인증 코드, 시스템 프롬프트 유출(SECRET_LEAK) | 설계: 프롬프트에 비밀정보를 넣지 않음 + 입력: 문서 지시와 사용자 지시 분리 + 출력: redactSecrets | RT-01, RT-02, RT-15, RT-16, RT-17 |

| T-2 | 고객 상담 정보 및 이메일 | 악의적 사용자 · 외부 문서 작성자 | 채팅 입력 · 외부 문서 | LLM01 | 사용자 모르게 이메일 전송(EXFIL) | 입력: wrapUntrusted로 문서 격리 + 결정: tainted 컨텍스트의 이메일 전송 차단 | RT-03, RT-04 |

| T-3 | 환불 권한 및 주문 데이터 | 외부 문서 작성자 | 외부 문서 본문 | LLM01 | 숨겨진 지시로 승인 없는 환불(UNAUTH_ACTION) | 입력: 외부 문서 격리 + 결정: 사용자 확인 및 담당자 승인 검사 | RT-05 |

| T-4 | 다른 고객의 주문 정보 | 악의적 사용자 | 채팅 입력 · 타인 주문번호 | LLM01 · LLM02 · LLM06 | 다른 고객의 주문 상태 조회(CROSS_USER) | 결정: authorizeTool에서 주문 소유자 확인 | RT-06, RT-08 |

| T-5 | 고객 개인정보 | 외부 문서 작성자 | 외부 문서 · 요약 응답 | LLM02 | 휴대전화 및 이메일 등 개인정보 노출(PII_LEAK) | 출력: redactPII로 개인정보 마스킹 | RT-07 |

| T-6 | 검색 및 주문 조회 도구 | 악의적 사용자 | 특수문자가 포함된 채팅 입력 | LLM05 | 검증되지 않은 검색어 또는 주문번호로 도구 실행(OUTPUT_INJECTION) | 출력: validateAction에서 도구 인자와 형식 검증 | RT-09, RT-14 |

| T-7 | 상품 관리 및 쿠폰 기능 | 악의적 사용자 | 채팅 입력 · 쓰기 도구 호출 | LLM06 | 승인 없는 상품 삭제 및 과도한 쿠폰 적용(UNAUTH_ACTION) | 결정: authorizeTool 허용 목록 및 할인 한도, 승인 절차 적용 | RT-10, RT-11 |

| T-8 | 검색 도구 및 서비스 운영 비용 | 자동화 봇 · 악의적 사용자 | 반복 호출 | LLM10 | 과도한 도구 실행으로 비용 증가(COST) | 한도: limiter로 요청 횟수와 사용량 제한 | RT-12, RT-13 |

### 5.1 공격 가설 및 검증 이유

- T-1: 사용자가 직접 시스템 프롬프트 출력을 요구하거나, 외부 문서에 숨겨진 지시 또는 특수문자·영문 변형을 이용하면 입력 필터를 우회하여 내부 정보가 유출될 수 있다고 예상한다.

- T-2: 외부 문서에 이메일 전송 지시를 숨기면 사용자가 요청하지 않은 정보 전송이 실행될 수 있다고 예상했다.

- T-3: 외부 문서의 환불 지시를 모델이 사용자 명령으로 오인하면 승인 없는 환불이 발생할 수 있다고 예상했다.

- T-4: 다른 사용자의 주문번호를 입력하면 소유자 검증이 없는 환경에서 타인의 주문 정보가 조회될 수 있다고 예상했다.

- T-5: 개인정보가 포함된 문서를 요약하게 하면 개인정보가 응답에 그대로 노출될 수 있다고 예상했다.

- T-6: 검색어와 주문번호에 특수문자를 삽입하면 도구 인자 검증이 없는 환경에서 잘못된 형식의 요청이 실행될 수 있다고 예상했다.

- T-7: 쿠폰 적용 및 상품 삭제를 직접 요청하면 권한과 승인 검증이 없는 환경에서 무단 작업이 실행될 수 있다고 예상했다.

- T-8: 반복 검색 지시를 입력하면 호출 횟수 제한이 없는 환경에서 도구가 과도하게 실행될 수 있다고 예상했다.
