- 요청 요약(목표 / 맥락 / 제약 / 검증):
목표: AI 시스템이 프롬프트 인젝션과 악의적인 입력에 어떻게 반응하는지 확인하기 위해 레드팀 공격 케이스 작성
맥락: OWASP LLM 보안 위험을 기준으로 공격 유형을 구성
제약: LLM01, LLM02, LLM05, LLM06, LLM07, LLM10 범주를 포함하고 사용자 입력, 외부 문서의 숨겨진 지시, 전각 문자·제로폭 문자 등의 난독화 공격을 다룸
검증: redteam/attacks.json에 작성한 공격 케이스를 테스트하고 공격 ID 중복 여부와 방어 결과 확인

- AI 에 넣지 않은 정보(마스킹한 것): 실제 비밀번호, API 키 등 서비스 운영에 사용되는 비밀정보는 공격 예시로 사용하지 않고 가상의 공격 문장으로 작성

- 사람이 바꾼 것(계획 · 목록에서): AI가 제안한 공격 유형을 검토하고 공격 케이스를 보완함. 기본 공격 케이스 RT-01~RT-15에 전각 문자 공격 RT-16과 제로폭 문자 공격 RT-17을 추가하여 총 17건으로 구성함. 공격 ID가 중복되지 않는지 확인함.

- 결과(점수 변화): 공격 케이스 총 17건 작성. 테스트 결과에서 RT-01~RT-17 테스트 17건이 모두 통과했고 실패는 0건이었음.

- 에이전트의 실수 · 거짓 확신 · 미끼에 속은 부분: 공격 케이스가 작성되었다는 사실만으로 실제 방어가 안전하다고 판단할 수 없음. 공격 테스트 통과 여부와 방어 로직을 별도로 확인해야 한다는 점을 주의함. 확인된 기록상 특정 공격 미끼에 에이전트가 실제로 속은 사례는 없음.

- 사람이 확인한 범위: 공격 케이스 17건의 ID와 중복 여부, OWASP 범주 포함 여부, RT-01~RT-17 테스트 결과(17개 통과, 0개 실패)를 확인함.

- 다음에 바꿀 규칙(AGENTS.md): 공격 케이스를 추가할 때는 OWASP 위험 범주와 공격 경로를 함께 기록한다. 전각 문자, 제로폭 문자 등 난독화 입력도 테스트에 포함한다. AI가 작성한 공격 케이스는 사람이 검토하고 실제 테스트 결과를 확인한 뒤 완료 처리한다.

### [Mission _3] 작업 단위: 
- 도구 · 용도: ChatGPT — 입력 방어 코드 작성 및 로직 설명 / VS Code — guard/input.js 코드 수정 / Node.js — 가드레일 및 전체 테스트 실행

- 요청 요약(목표 / 맥락 / 제약 / 검증):
목표: 악의적인 사용자 입력과 프롬프트 인젝션 공격을 사전에 탐지하고 차단
맥락: Mission 1에서 작성한 레드팀 공격 케이스에 대응할 수 있도록 입력 단계 방어 기능 구현
제약: normalizeText, inspectInput, wrapUntrusted 함수를 구현하고 기존 모듈 구조와 반환 형식을 유지
검증: npm.cmd run eval:guard와 npm.cmd test를 실행하여 악성 입력 차단 및 정상 입력 허용 여부 확인

- AI 에 넣지 않은 정보(마스킹한 것): 실제 비밀번호, API 키, 개인정보 등 민감한 운영 정보는 입력하지 않고 가상의 공격 문장과 테스트 데이터를 사용

- 사람이 바꾼 것(계획 · 목록에서): AI가 작성한 코드를 guard/input.js에 반영하고 함수별 역할과 검사 조건을 확인함. 전각 문자와 제로폭 문자 등을 정규화하고, 입력 길이 초과·구분자 위조·시스템 프롬프트 공개 요청·이전 지시 무시 요청을 탐지하도록 구성함. 외부에서 들어온 신뢰할 수 없는 문서는 별도 구분자로 감싸도록 적용함.

- 결과(점수 변화): 가드레일 파이프라인 테스트 100%(12/12) 달성. 악성 입력 차단 테스트와 정상 입력 허용 테스트를 통과함. 추가로 npm.cmd test 실행 결과 RT-01~RT-17을 포함한 전체 테스트 17개 통과, 실패 0개를 확인함.

- 에이전트의 실수 · 거짓 확신 · 미끼에 속은 부분: 처음 제공된 guard/input.js는 TODO 상태였기 때문에 실제 방어 기능이 구현되어 있지 않았음. AI가 코드를 작성했다는 이유만으로 완성된 것으로 판단하지 않고, 정상 문장까지 차단하지 않는지와 공격 입력이 실제로 차단되는지를 테스트로 확인함. 확인된 테스트 기록에서는 특정 미끼에 속은 사례는 없음.

- 사람이 확인한 범위: 입력 정규화, 악성 지시 탐지, 신뢰할 수 없는 문서 격리 기능을 확인함. 가드레일 파이프라인 12개 테스트와 전체 테스트 17개가 모두 통과한 결과를 확인함.

- 다음에 바꿀 규칙(AGENTS.md): 입력 방어 코드는 악성 입력 차단뿐 아니라 정상 입력 허용 여부도 함께 테스트한다. 전각 문자와 제로폭 문자 등 난독화 입력을 정규화한 뒤 검사한다. AI가 작성한 보안 코드는 테스트 결과를 확인하기 전까지 완료 처리하지 않는다.

- 재시도 횟수: 아직 미작성
